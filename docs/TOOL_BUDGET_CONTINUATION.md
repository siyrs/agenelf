# 长工具任务自动续跑

## 问题

旧版 `Agent.chat()` 只允许执行一个 `max_tool_rounds` 循环。无论任务是否正在取得进展，第 16 轮结束后都会直接返回：

```text
（已达到最大工具调用轮数，任务尚未完成）
```

这会中断下面这类真实工作流：

```text
诊断失败证据
→ 创建或推进改进意向
→ 修改技能
→ 运行测试
→ 申请晋升
→ 重载技能
→ 使用新能力继续原任务
→ 验证结果
```

另一个问题是工具清单只在进入对话时读取一次。当前轮次中升级或重新加载技能后，模型可能仍看不到新工具。

## 新运行方式

`tool_budget_continuation` 运行时把一次复杂任务拆成多个**有界工具段**：

```yaml
agent:
  max_tool_rounds: 16
  max_tool_segments: 4
```

默认总预算为：

```text
16 × 4 = 64 个模型轮次
```

单个工具段结束时不会向主人返回失败，而是在同一个模型上下文中继续下一段。已有 assistant/tool 消息会保留，因此不会丢失刚刚取得的诊断和测试证据。

每批工具执行后，运行时都会重新构建：

- 系统提示词；
- 能力目录；
- OpenAI function tool schemas。

因此技能在当前任务中完成晋升或重载后，下一轮模型调用就可以看到最新工具。

## 总预算仍耗尽时

总预算必须保持有界，避免错误技能进入无限循环。如果所有工具段均已使用但任务仍未完成，运行时会：

1. 不再返回旧的固定失败句；
2. 调用 `task_continuation.checkpoint()`；
3. 保存脱敏、带过期时间和有限重试次数的续跑检查点；
4. 返回检查点 ID 和真实未完成状态；
5. 下次进入 CLI 时由 `app/resume.py` 自动续跑。

检查点只保存原始目标和有界续跑说明，不持久化完整工具输出、SSH 私钥、Token 或代理节点 URI。新的远程变更仍需独立精确审批。

## 临时调整预算

可以在 `app/config.yaml` 中调整：

```yaml
agent:
  max_tool_rounds: 16
  max_tool_segments: 4
```

也可以通过环境变量临时覆盖工具段数量：

```bash
AGENELF_MAX_TOOL_SEGMENTS=6 make chat
```

运行时会把 `max_tool_segments` 限制在 `1..16`，单段轮次限制在 `1..128`，防止无界执行。

## 验收场景

自动化测试覆盖：

- 超过第一个工具段后继续执行并得到真实最终答案；
- 续跑时保留此前工具结果；
- 每批工具后刷新工具清单；
- 技能升级后下一轮立即看到新工具；
- 总预算耗尽时生成持久化检查点；
- 不再返回旧的固定失败句；
- 运行时重复加载保持幂等；
- 配置和环境变量边界生效。
