# ADR-0001：Agenelf 采用策略单一真源与三权分离

- 状态：Accepted
- 日期：2026-07-25

## 背景

Agenelf 正从聊天和单机工具逐步演进为多服务器运维、代码修复、验证、移动和语音私人管家。能力扩大后，如果风险规则只存在于 Prompt、文档或多个 Runner 的重复代码中，会产生不一致、绕过和不可审计问题。

## 决策

1. 使用 `policy/safety-constraints.v1.yaml` 作为治理语义的机器可校验基线；
2. 使用 Agent 提议、主人裁决、确定性 Runner 执行的三权分离；
3. 模型永远不是授权主体；
4. 高风险操作分为 `change`、`privileged`、`irreversible`，主人可以按要求精确授权；
5. `forbidden` 只用于治理绕过、凭据泄露、审计破坏和自我批准等永久红线；
6. 授权绑定规范化载荷、风险、nonce 和有效期，并单次消费；
7. 自进化不能修改策略、授权、Runner、CI 或主分支，除非通过人类主导的 PR 流程；
8. 每次策略变更必须更新测试和文档。

## 结果

优点：

- 风险语义统一；
- 主人可理解并授权危险操作；
- 模型和 Prompt 不能静默扩权；
- Runner 可独立校验；
- 策略可进入 CI；
- 移动和语音可复用同一控制面。

代价：

- 新能力必须先定义 schema 和风险；
- 高风险任务需要额外交互；
- 策略升级需要兼容和迁移；
- 不能用任意 Shell 快速覆盖所有需求。

## 被否决方案

### 让 LLM 判断是否安全

否决原因：模型输出不稳定、可受注入影响，不能成为授权或策略引擎。

### Agent 直接持有 root SSH

否决原因：权限范围过大，无法实现能力隔离和最小权限。

### 所有危险任务永久拒绝

否决原因：违背私人管家的目标。主人完成精确授权后，系统应忠实执行合法的高风险任务。

### 主人一句“全部授权”永久放行

否决原因：无法绑定目标和参数，不能撤销，容易被任务漂移和 Prompt injection 利用。
