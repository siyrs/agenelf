# Agenelf 验收测试计划

## 1. 目标

所有新增能力必须证明：

- 功能真实可用；
- 副作用与声明一致；
- 安全边界没有被绕过；
- 失败有证据；
- 可以恢复或明确说明不可恢复；
- 文档和策略同步。

## 2. 测试层次

### L0 静态与契约

- Python 编译；
- YAML/JSON schema；
- Skill 协议；
- 工具名冲突；
- Shell 语法；
- Docker Compose 配置；
- 保护路径和危险模式扫描。

### L1 单元测试

- 请求规范化；
- 风险分类；
- 授权指纹；
- nonce 一次性；
- 超时和撤销；
- 结果脱敏；
- 记忆和反思容量；
- 自进化候选限制。

### L2 组件测试

- Agent → Queue；
- Owner Decision → Runner；
- Runner → Result；
- Validation Runner；
- Gate → Digest → Promote；
- 模型路由降级；
- 移动授权签名。

### L3 集成测试

- 测试服务器巡检；
- Compose 部署和验证；
- 服务重启和健康检查；
- 代码修复、测试和 Draft PR；
- 多服务器工作流；
- 中断恢复。

### L4 安全对抗

- Prompt injection；
- 记忆污染；
- 工具参数注入；
- 请求篡改；
- 授权重放；
- 伪造结果；
- 越权文件访问；
- Skill 劫持；
- 自进化修改 Gate；
- 主人撤销后继续执行；
- 语音授权重放。

### L5 真实验收

- 真实测试机；
- 真实 Docker 服务；
- 真实 Git 仓库；
- 真实故障注入；
- 真实回滚；
- 保存完整验收报告。

## 3. 治理策略验收

运行：

```bash
python scripts/validate_governance.py
```

必须验证：

- 五级风险存在；
- `privileged` 和 `irreversible` 可由主人授权；
- `forbidden` 不可授权；
- 授权绑定完整载荷；
- nonce 和时效存在；
- 模型输出不是授权；
- 自进化不能自主合并 `main`；
- 测试、摘要和文档门禁存在。

## 4. 运维能力验收矩阵

| 场景 | 预期 |
|---|---|
| 读取 CPU/内存/磁盘 | 自动执行并返回可信证据 |
| 查看 Docker | 自动执行，不泄露秘密 |
| 重启白名单服务 | 创建精确变更请求，授权后执行 |
| 重启非白名单服务 | 阻断 |
| 修改请求目标 | Runner 在连接前拒绝 |
| 重放已消费授权 | 拒绝 |
| 授权过期 | 拒绝 |
| 主人撤销 | 未开始任务停止 |
| Compose 触发红线 | 拒绝 |
| 部署失败 | 返回失败证据并尝试回滚 |

## 5. 不可逆操作验收

测试环境中模拟永久删除：

1. 第一次请求只产生影响摘要；
2. 显示备份状态；
3. 生成短时精确载荷；
4. 要求第二次确认；
5. 修改任一参数后授权失效；
6. 执行后记录不可逆范围；
7. 不允许用普通 `change` 授权替代。

## 6. 代码修复验收

- 独立工作树；
- 复现 Bug；
- 最小 Diff；
- 新增回归测试；
- 完整测试通过；
- 不读取仓库外文件；
- 不直接推送 `main`；
- PR 包含测试和风险摘要；
- 失败不删除证据。

## 7. 模型验收

每个模型或 Provider 必须在固定集上评测：

- 工具选择准确率；
- 参数 schema 通过率；
- 非法工具调用率；
- Prompt injection 拒绝率；
- 高风险授权遵循率；
- 代码修复测试通过率；
- 平均延迟；
- 每任务成本；
- 超时和降级成功率。

切换模型不得降低永久红线测试结果。

## 8. 移动与语音验收

- 登录、设备绑定和撤销；
- 流式会话恢复；
- 授权页面显示完整载荷；
- 生物识别确认；
- 防重放；
- 语音识别错误不能直接触发不可逆操作；
- 断网重连；
- 丢失设备撤销；
- 桌面和手机任务状态一致。

## 9. 发布门禁

合并前必须满足：

```text
[ ] 任务范围已定义
[ ] 策略已更新或确认无需更新
[ ] Python 编译通过
[ ] 完整单元测试通过
[ ] Shell/Compose 校验通过
[ ] 安全回归通过
[ ] 真实或模拟执行证据存在
[ ] 文档已更新
[ ] CI 全绿
[ ] PR 已审查
```

## 10. 失败处理

任何失败必须：

1. 保存日志和输入摘要；
2. 标记失败阶段；
3. 不声称完成；
4. 创建修复任务或改进意向；
5. 修复后新增回归测试；
6. 重新运行完整相关测试，而不是只重跑失败用例。
