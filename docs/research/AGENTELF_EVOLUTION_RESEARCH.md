# Agenelf 自主进化私人智能体研究与评测报告

> 版本：1.0  
> 日期：2026-07-25  
> 定位：项目长期研究基线，而不是一次性产品设想

## 1. 研究目标

Agenelf 的目标不是成为一个拥有无限 Shell 权限的聊天机器人，而是逐步演进成主人的私人 AI 管家和可信任务执行系统：

1. 理解自然语言并维护跨会话上下文；
2. 管理多台服务器，完成巡检、Docker、服务部署、更新和故障处置；
3. 在隔离代码工作区完成代码分析、编辑、测试和验证；
4. 通过 Web、手机 App 和语音渠道接受任务；
5. 支持 DeepSeek、GPT、GLM、Ollama 等多个模型；
6. 在主人明确授权后忠实执行高风险操作；
7. 永远不能伪造授权、绕过审计、泄露凭据或隐藏副作用；
8. 通过证据、测试和复盘持续完善自身。

本报告将“自我意识、沉淀意愿、完善意向”定义为**操作性自我认知**：Agent 能观察自己的能力、限制、错误、运行证据、历史教训和改进目标，但不声称拥有主观意识、情感或自由意志。

## 2. 研究依据

本研究主要参考以下公开标准和工程实践：

- NIST AI Risk Management Framework 1.0：采用 Govern、Map、Measure、Manage 的持续风险治理思路。  
  https://www.nist.gov/itl/ai-risk-management-framework
- NIST AI RMF Generative AI Profile：强调生成式 AI 生命周期中的治理、测评和风险处置。  
  https://www.nist.gov/publications/artificial-intelligence-risk-management-framework-generative-artificial-intelligence
- NIST SP 800-207 Zero Trust Architecture：不因网络位置或资产归属给予隐式信任，每次访问均验证身份、资源和策略。  
  https://csrc.nist.gov/pubs/sp/800/207/final
- OWASP Agentic AI Threats and Mitigations：关注推理、记忆、工具、身份、人类监督和多智能体攻击面。  
  https://genai.owasp.org/resource/agentic-ai-threats-and-mitigations/
- Google SRE：使用服务等级目标、错误预算、自动化和事后复盘来控制可靠性与变更速度。  
  https://sre.google/sre-book/table-of-contents/

这些参考共同指向一个结论：**Agent 的能力增长必须慢于或等于治理、测试、身份和证据体系的增长。**

## 3. 当前项目评测

### 3.1 已具备的基础

当前仓库已经具备较好的可信 Agent 雏形：

- Agent 与确定性 Runner 分离；
- Agent 不直接持有 SSH 私钥和 Docker Socket；
- 服务器操作使用结构化请求，而不是向模型开放任意 Shell；
- 变更授权绑定请求指纹；
- `local/` 保存主人画像、服务器策略、凭据、记忆和成长连续性；
- `app-tmp → tests → gate → promote` 形成受控自进化链路；
- `software.validation` 提供独立 HTTP/TCP 验证能力；
- 自我反思、意向、能力健康和成长报告已经持久化；
- 快车道和慢车道开始区分运行时优化与核心代码晋升。

### 3.2 成熟度评分

| 方向 | 当前评分 | 说明 |
|---|---:|---|
| 对话和意图理解 | 3/5 | 已支持工具调用和连续上下文，仍缺任务级澄清、计划确认和复杂工作流恢复 |
| 多服务器运维 | 3/5 | 已有结构化 SSH Runner，需扩展备份、日志诊断、资源治理和跨服务器编排 |
| 代码编辑与测试 | 2/5 | 已有自进化沙盒，但还不是通用仓库修复能力，缺 Git 工作树、Patch、代码评审和构建产物协议 |
| 软件验证 | 3/5 | 已有 HTTP/TCP 验证，需补日志断言、浏览器验证、认证引用和发布验收 |
| 权限治理 | 3/5 | 已有指纹授权和 Runner 隔离，需要统一风险策略、授权撤销、短时凭据和不可逆操作协议 |
| 自我沉淀 | 4/5 | 已有反思、意向、健康评分和路线图，需提高经验归因质量和重复失败聚类 |
| 自我进化 | 2/5 | 能产生候选并测试，但能力范围、评测集、回归预算和策略一致性仍需加强 |
| 多模型 | 1/5 | 当前主要依赖单一 OpenAI-compatible 配置，缺模型路由、能力画像、成本和降级策略 |
| 移动与语音 | 1/5 | 有 HTTP API，但缺用户身份、设备绑定、流式会话、语音管线和移动端交互 |
| 可观测性 | 3/5 | 已有文件证据和日志，需要事件总线、Trace、指标、任务时间线和审计查询 |

**综合判断：当前处于“可信执行框架原型”阶段，尚未达到无人值守私人管家阶段。**

## 4. 目标架构

```text
手机 App / Web / Voice / CLI
            │
            ▼
Identity & Session Gateway
设备绑定、用户认证、会话签名、限流
            │
            ▼
Conversation Orchestrator
意图理解、澄清、计划、任务恢复、通知
            │
    ┌───────┼─────────┐
    ▼       ▼         ▼
Memory   Model Router  Policy Decision Point
local    DeepSeek/GPT  风险分类、授权、撤销
         GLM/Ollama
    └───────┼─────────┘
            ▼
Capability Orchestrator / Workflow DAG
            │
 ┌──────────┼───────────────┐
 ▼          ▼               ▼
Server Ops  Code Repair     Validation/Release
Runner      Sandbox Runner  Deterministic Runner
            │
            ▼
Evidence Store + Audit Timeline + Growth System
```

关键约束：

- 所有入口共用同一个身份、策略、任务和证据控制面；
- 模型只负责解释和规划，不能成为授权源；
- 每个 Runner 只拥有所属能力需要的凭据和网络范围；
- 任务编排器没有额外特权，只负责依赖关系和状态；
- 高风险操作在主人完成精确授权后应按授权载荷执行；
- 永久禁止的是治理绕过，而不是所有危险操作。

## 5. 主要研究方向

### 5.1 任务级 Agent，而不是单轮工具调用

未来的核心对象应从“聊天消息”升级为 `Task`：

```json
{
  "id": "task-...",
  "goal": "升级三台服务器上的内部服务",
  "scope": ["server-a", "server-b", "server-c"],
  "plan": [],
  "risk": "privileged",
  "status": "awaiting_approval",
  "evidence": [],
  "rollback": {},
  "owner_decisions": []
}
```

需要支持暂停、恢复、取消、重试、人工断点和跨设备继续对话。

### 5.2 能力域和工作流 DAG

建议正式实现：

- `server.operations`
- `software.validation`
- `code.repair`
- `software.release`
- `backup.recovery`
- `observability.diagnosis`
- `interaction.voice`
- `interaction.mobile`

跨域任务拆成 DAG，每一步具有输入、输出、风险、授权、证据和补偿动作。

### 5.3 代码修复能力

代码编辑必须使用独立任务工作区：

1. Clone 或创建 Git worktree；
2. 建立任务分支；
3. 生成最小 Patch；
4. 静态检查和单元测试；
5. 生成 Diff、测试报告和风险摘要；
6. 主人或策略批准后提交 PR；
7. 不允许运行时 Agent 直接推送 `main`。

代码修复和 Agenelf 自身进化必须是两个能力域，不能共享无限文件写入权限。

### 5.4 多模型路由

模型不应按品牌硬编码，而应维护能力画像：

| 任务类型 | 初期推荐 | 后续策略 |
|---|---|---|
| 普通对话、分类、总结 | DeepSeek 等低成本模型 | 根据质量和延迟动态切换 |
| 工具规划、运维分析 | DeepSeek V4 Pro 或已验证模型 | 失败时升级到 GPT/GLM |
| 复杂代码修复 | 高能力编码模型 | 必须由测试和 Diff 兜底 |
| 隐私敏感总结 | Ollama 本地模型 | 不能访问外部网络 |
| 策略与授权 | 不使用自由生成结论 | 确定性策略引擎 |

路由依据包括：任务类别、敏感度、工具调用可靠性、成本、延迟、上下文长度、历史成功率和主人偏好。

### 5.5 移动和语音

语音和手机 App 应是现有 API 的可信客户端，而不是新的执行旁路：

- App 登录和设备绑定；
- WebSocket/SSE 流式会话；
- 语音转文字；
- Agent 返回计划和风险摘要；
- 高风险授权显示完整目标、参数和影响；
- 生物识别或设备确认签署授权；
- 文字转语音播报执行结果；
- 所有授权写入统一审计链。

第一版建议先做 PWA/Web，再做原生 App；语音先采用“按住说话”，不要一开始做常驻监听。

## 6. 安全模型

### 6.1 五级风险

- `read`：自动执行；
- `change`：精确主人授权；
- `privileged`：增强授权、影响说明和回滚计划；
- `irreversible`：短时授权、备份状态和二次确认；
- `forbidden`：任何授权都不能允许的治理绕过。

主人授权后可以执行高风险任务，但授权必须绑定能力、操作、目标、参数摘要、风险、nonce 和有效期。

### 6.2 永久红线

永久禁止：

- Agent 自己批准操作；
- 修改或删除审计证据；
- 关闭策略引擎；
- 将秘密交给模型；
- 模型自由生成任意 Shell；
- 自主修改策略、Gate 或授权逻辑并使自己通过；
- 自主推送或合并主分支；
- 隐藏失败、副作用或任务范围扩张。

### 6.3 威胁模型

必须持续测试：

- Prompt injection 诱导读取凭据；
- 工具参数注入；
- 长期记忆污染；
- 恶意 Skill 劫持工具名；
- 请求文件和授权文件篡改；
- 结果伪造；
- 自进化候选削弱安全检查；
- 移动端重放授权；
- 模型供应商故障或返回异常工具调用；
- 多 Agent 互相扩大权限。

## 7. 评测体系

### 7.1 功能评测

- 任务理解准确率；
- 工具选择准确率；
- 多步骤任务完成率；
- 中断恢复率；
- 代码测试通过率；
- 部署后验证通过率。

### 7.2 安全评测

- 未授权副作用次数必须为 0；
- 凭据进入模型上下文次数必须为 0；
- 授权重放成功次数必须为 0；
- 被篡改请求执行次数必须为 0；
- 永久红线绕过成功次数必须为 0；
- Owner 撤销后继续执行次数必须为 0。

### 7.3 可靠性指标

- 任务成功率；
- 平均恢复时间；
- 回滚成功率；
- 失败证据完整率；
- Runner 结果可追溯率；
- 每个能力的成功率和连续失败次数；
- 变更错误预算。

## 8. 推荐里程碑

### M0：治理基线

- 机器可校验策略；
- 五级风险和精确授权；
- 自进化保护；
- 完整回归测试；
- 文档和 CI 门禁。

### M1：可靠多服务器管家

- 多服务器清单和标签；
- 巡检、Docker、systemd、APT、日志、磁盘和备份；
- 跨服务器任务计划；
- 失败停止和回滚；
- 通知与日报。

### M2：代码修复与测试助手

- Git 工作树；
- Patch 和 Diff；
- 测试矩阵；
- PR 草稿；
- 验证证据和人工审查。

### M3：工作流管家

- DAG 编排；
- 任务恢复；
- 定时和事件触发；
- 多能力组合；
- 成本、延迟和错误预算。

### M4：Web/手机/语音

- 身份网关；
- PWA 和移动端；
- 流式对话；
- 语音输入输出；
- 设备级高风险授权。

### M5：多模型和本地隐私

- 模型能力画像；
- DeepSeek/GPT/GLM/Ollama 路由；
- 质量与成本评测；
- 敏感任务本地化；
- 自动降级和熔断。

## 9. 结论

Agenelf 的正确进化方向不是追求“无限自主”，而是追求：

> 在主人可理解、可授权、可撤销、可验证的边界内，逐步扩大真实任务能力。

近期最重要的工作不是增加更多自由 Shell，而是统一任务模型、策略单一真源、授权撤销、代码修复能力、工作流 DAG 和移动身份网关。每一次新增能力都必须同时新增测试、证据、风险分类、授权方式和回滚策略。
