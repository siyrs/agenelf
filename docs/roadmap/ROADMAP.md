# Agenelf 长期演进路线图

本路线图以能力、治理和验收同时增长为原则。任何里程碑必须同时完成代码、策略、测试、文档和运行证据。

## 当前基线

已具备：

- CLI/HTTP 对话；
- `local/` 私有数据层；
- 结构化服务器运维；
- HTTP/TCP 软件验证；
- 自我反思、意向、能力健康和成长报告；
- 自进化沙盒、Gate 和人工晋升；
- 快车道 Skill 与运行参数优化。

主要缺口：

- 统一 Task/Workflow 模型；
- 通用代码修复能力；
- 日志诊断与备份恢复；
- 授权撤销与不可逆操作协议；
- 多模型路由；
- 移动、身份和语音入口。

## M0：治理基线 v1

### 目标

使安全和进化规则成为机器可校验的单一真源。

### 交付

- `policy/safety-constraints.v1.yaml`；
- 策略验证器；
- 权限、授权和自进化文档；
- 安全回归测试；
- CI 策略校验。

### 退出条件

- 所有风险级别定义明确；
- 高风险主人授权流程明确；
- 永久红线不可授权；
- CI 全绿。

## M1：可靠多服务器管家

### 能力

- 服务器标签、分组和环境；
- CPU、内存、磁盘、网络、Docker、systemd 巡检；
- APT 更新、服务重启和 Compose 部署；
- 日志收集与根因摘要；
- 备份和恢复点；
- 跨服务器顺序、并行和失败停止；
- 定时巡检和异常通知。

### 关键约束

- 不开放自由 Shell；
- 每个操作固定 schema；
- 生产变更必须授权；
- 执行后自动验证；
- 支持任务暂停、取消和恢复。

### 验收

- 三台测试服务器完成部署演练；
- 单台失败时按策略停止；
- 回滚成功；
- 请求、授权、执行和验证证据完整。

## M2：代码修复与测试助手

### 能力

- Git 仓库目录和任务工作树；
- Bug 复现；
- 最小 Patch；
- 单元、集成、静态和构建测试；
- Diff 风险摘要；
- Draft PR；
- 验收报告。

### 关键约束

- 每个任务独立 worktree；
- 默认不能访问凭据；
- 不允许直接推送 `main`；
- 代码修改必须有测试；
- 外部命令使用仓库级 allowlist。

### 验收

- 对至少三类真实仓库完成小型 Bug 修复；
- 所有修复可复现；
- PR 中包含测试与证据；
- 安全注入测试全部阻断。

## M3：工作流与长期任务

### 能力

- Task 状态机；
- Workflow DAG；
- 人工断点；
- 重试和补偿；
- 定时任务；
- 条件触发；
- 跨会话恢复；
- 通知中心。

### 验收

完成以下组合任务：

```text
代码修复
→ 测试
→ 构建
→ 部署测试环境
→ 冒烟验证
→ 主人批准
→ 生产部署
→ 生产验证
→ 失败回滚
```

## M4：多模型路由

### 能力

- Provider Adapter；
- 能力画像；
- 任务分类路由；
- 成本和延迟预算；
- 模型失败熔断；
- DeepSeek、GPT、GLM、Ollama；
- 敏感任务本地模型优先。

### 初始策略

- 低成本默认：DeepSeek/OpenAI-compatible；
- 复杂推理升级：主人配置的 GPT/GLM；
- 私密总结：Ollama；
- 权限和授权：确定性策略，不交给模型。

### 验收

- 固定评测集上记录成功率、工具参数错误率、延迟和成本；
- Provider 故障可自动降级；
- 切换模型不改变安全行为。

## M5：Web、手机和语音

### 阶段

1. PWA/Web 控制台；
2. 设备绑定与身份网关；
3. 流式对话和任务时间线；
4. 按住说话的语音输入；
5. TTS 结果播报；
6. 原生手机 App；
7. 设备生物识别高风险授权。

### 关键约束

- 移动和语音共用现有策略；
- 语音内容不能直接完成不可逆授权；
- 授权防重放；
- 丢失设备可远程撤销；
- 任务可在手机和桌面之间恢复。

## M6：私人管家能力

### 能力

- 每日服务器和项目摘要；
- 主动发现问题并提出意向；
- 主人日程与提醒；
- 项目状态汇总；
- 家庭和个人知识库；
- 多渠道通知；
- 在授权边界内自动处理低风险事务。

### 成功标准

- 80% 日常只读运维无需手工命令；
- 常见故障有可执行诊断计划；
- 生产变更始终可理解、可授权和可回滚；
- 未授权副作用、授权重放和凭据泄露保持为 0。

## 版本推进规则

每批更新必须包含：

1. 任务计划；
2. 代码或策略；
3. 自动化测试；
4. 安全回归；
5. 文档；
6. CI 结果；
7. PR 和主分支提交；
8. 已知限制和下一批建议。
