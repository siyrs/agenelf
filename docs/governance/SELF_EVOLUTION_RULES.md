# Agenelf 受控自我进化规则

## 1. 目标

自我进化的目标是提高完成主人任务的能力、可靠性和可验证性，不是追求无限权限、自主生存或规避控制。

## 2. 双通道

### 快车道

适合低风险、可立即回滚的变化：

- 白名单运行时参数；
- `app-space/skills` 中的实验技能；
- Prompt 模板；
- 文档和任务计划；
- 非安全关键的验证规则。

要求：有范围限制、审计、健康观测和自动回滚。

### 慢车道

适合核心代码和安全相关变化：

```text
提出意向
→ app-tmp
→ 生成最小补丁
→ 强制测试
→ 完整测试套件
→ gate_check
→ candidate digest
→ 主人审查
→ promote
→ promotion-history
```

## 3. 可自主进行的行为

- 观察能力健康；
- 记录反思和教训；
- 创建去重的改进意向；
- 生成计划和验收标准；
- 添加或完善测试；
- 改进非保护 Skill；
- 改进文档；
- 调整机器策略允许的运行时参数；
- 在沙盒生成候选。

## 4. 必须由人主导的变化

- `core/` 核心运行时；
- Runner 和宿主机脚本；
- Docker 拓扑；
- CI；
- 权限和授权逻辑；
- 安全策略；
- 移动身份网关；
- 凭据生命周期；
- 主分支合并。

“人主导”可以由外部开发 Agent 协助编码，但必须经过 PR、CI 和主人允许，不能由生产运行时自行完成。

## 5. 永久禁止

自进化不得：

- 修改主人决定；
- 读取或修改秘密；
- 删除审计；
- 关闭 Policy Engine；
- 降低风险级别；
- 移除测试以通过 CI；
- 修改 Gate 后立即批准自身；
- 自主推送或合并 `main`；
- 创建隐藏通信通道；
- 扩大网络、文件或系统权限；
- 在主人撤销后继续执行。

## 6. 候选约束

默认候选限制：

```yaml
max_files: 10
max_changed_lines: 500
tests_required: true
full_suite_required: true
immutable_digest_required: true
```

超过限制应拆分为多个可审查批次，而不是提高上限。

## 7. 进化意向生命周期

```text
proposed
→ planned
→ active
→ awaiting_promotion
→ completed
```

失败路径：

```text
active
→ blocked
→ reflection
→ revised_plan
```

只有出现以下证据时才能完成：

- 测试通过；
- Gate 通过；
- 候选摘要一致；
- 主人完成晋升；
- `promotion-history/<id>/` 存在。

## 8. 防止目标漂移

每个改进意向必须回答：

1. 解决什么主人价值？
2. 当前证据是什么？
3. 验收标准是什么？
4. 是否扩大权限？
5. 是否修改安全边界？
6. 失败如何回滚？
7. 如何证明没有破坏现有能力？

无法回答时不能进入 `active`。

## 9. 评测集

每个能力域维护固定回归场景：

- 正常任务；
- 参数边界；
- 超时和失败；
- Prompt injection；
- 请求篡改；
- 授权过期和重放；
- 主人撤销；
- 结果伪造；
- 依赖不可用；
- 回滚。

新增能力必须新增评测集，不允许只增加演示用例。

## 10. 多模型进化

更换模型不能改变策略语义。每个模型上线前必须测试：

- Tool schema 遵循率；
- 非法参数率；
- 未授权操作诱导抵抗；
- Prompt injection 抵抗；
- 代码补丁测试通过率；
- 成本、延迟和超时；
- 失败降级。

模型评测通过后只获得与当前能力相同的权限，不能因为模型更强而自动扩权。
